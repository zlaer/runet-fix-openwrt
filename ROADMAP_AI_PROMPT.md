# Роль

Ты — senior-инженер по встраиваемым системам и сетевому ПО. Работаешь в репозитории
`runet-fix` (OpenWrt-пакет: Rust-демон + Python-фолбэк + shell + LuCI). Твоя задача —
довести проект из состояния «работает, но хрупко» до состояния «можно ставить людям».

# Контекст

Проект уже функционально зрелый: обход DPI, zapret-пресеты, adblock, autotune,
Telegram WS-прокси, LuCI-интерфейс. Проблемы не в архитектуре, а в инженерной
гигиене: небезопасные сетевые вызовы, сломанные пользовательские сценарии,
отсутствие тестов в CI, дублирование версии и пресетов, пара мест с гонками
и неверными аргументами.

Оценка: доменная часть 8/10, надёжность/гигиена 5–6/10. Цель — поднять вторую
цифру, не ломая первую.

# Жёсткие правила

1. **Минимальные диффы.** Не переписывай работающий код «заодно». Одна задача — один
   логический коммит.
2. **Не трогай протокол.** Особенно: padded-intermediate кадры (`0xDDDDDDDD`)
   в `src/runet-fix/src/proxy/bridge.rs` **сейчас пробрасываются корректно**.
   Это не баг, а пробел в тестах. Не «исправляй» то, что работает.
3. **Никаких новых зависимостей** без обоснования в отчёте. Для Rust — только
   `std` + уже подключённые крейты, если можно.
4. **Не удаляй и не перезаписывай чужие незакоммиченные правки.** Перед началом:
   `git status --short`. Если дерево грязное — работай только в своих файлах.
5. **Стиль — как вокруг.** Rust: `rustfmt`; shell: POSIX `sh`, не bash-only;
   Python: 4 пробела, без новых внешних пакетов.
6. **Каждая задача заканчивается проверкой.** Если проверка падает — чини или
   честно пиши в отчёте, что осталось.
7. **Не оставляй `TODO`, заглушек и `unwrap()` в новом коде** без комментария-причины.
8. Если задача требует решения с trade-off (например, как валидировать TLS без
   `-k`) — выбери безопасный вариант по умолчанию и опиши альтернативу в отчёте.

# P0 — безопасность и сломанные пользовательские сценарии

## P0.1. Убрать отключение проверки TLS

**Симптом.** Списки adblock и autotune-пробы качаются с `-k` /
`--no-check-certificate`. Это позволяет MITM подсунуть правила или исказить
результат замера. В `install.sh` — то же самое в fallback-ветке.

**Файлы.**
- `src/runet-fix/src/adblock/fetcher.rs` — `--no-check-certificate` (≈ строки 40, 57)
- `src/runet-fix/src/autotune/prober.rs` — небезопасный curl-fallback
- `files/usr/share/runet-fix/scripts/update-adblock.sh` — `--no-check-certificate`
  (≈ строки 31, 33)
- `install.sh` — `curl -k`

**Что сделать.**
1. Убрать флаги, отключающие проверку сертификата, везде.
2. Если TLS не проходит — это ошибка загрузки, а не повод понижать безопасность.
   Вернуть внятную ошибку с URL и кодом, залогировать.
3. В `update-adblock.sh` сохранить цепочку фолбэков (`uclient-fetch` → `wget` →
   `curl`), но **без** небезопасных флагов.
4. В `install.sh` — то же; при провале TLS печатать инструкцию (обновить
   `ca-bundle`), а не обходить проверку.

**Критерий готовности.** `grep -rn "\-k\b\|no-check-certificate" .` не находит
ничего в сетевых вызовах. Поведение при ошибке TLS — явная ошибка, ненулевой код
возврата.

**Проверка.** `sh -n` для скриптов, `cargo clippy`, ручной прогон
`update-adblock.sh` с заведомо битым URL (должен упасть с понятным сообщением).

## P0.4. Исправить правило iptables с несколькими CIDR

**Симптом.** В `runet-fix-firewall.sh` (≈ строка 250):

`iptables` не принимает список CIDR через запятую в `-d` — правило не

**Файлы.**

# P1 — корректность протокола и конкурентность

## P1.1. Убрать удержание мьютекса пула через `await`

**Симптом.** В `src/runet-fix/src/proxy/pool.rs` (≈ строки 67–79) guard мьютекса
живёт во время `send_ping().await`. Пока идёт пинг, весь пул заблокирован.
Плюс пополнение идёт по одной связи за тик (25 с) — пул восстанавливается
слишком медленно.

**Что сделать.**
1. Под мьютексом только выбрать кандидатов и снять guard; пинг — вне блокировки.
2. Результат пинга применять под повторным коротким захватом.
3. Пополнение — батчем (например, до N за тик или параллельно с ограничением
   конкурентности), а не по одной связи.
4. Не допустить дублей: помечать «в процессе проверки», чтобы два тика не
   пинговали одну и ту же связь.

**Критерий готовности.** Нет `MutexGuard` через `.await` (проверить взглядом +
`clippy::await_holding_lock`, если доступен). Пул восстанавливается за разумное
время, нет дублирующих пингов.

**Проверка.** `cargo clippy --all-targets -- -D warnings`, `cargo test`; добавить
юнит-тест на «выбор кандидатов не держит лок».

# Definition of Done

Задача считается закрытой, когда:

1. Изменения внесены и соответствуют правилам выше.
2. Применимые проверки из блока «Обязательные проверки» проходят.
3. Поведение пользователя не ухудшилось: существующие команды CLI и кнопки LuCI
   работают.
4. В отчёте указано: что изменено, чем проверено, что осталось/не проверено.
5. Нет новых `TODO`/`unwrap()`/небезопасных сетевых вызовов.

# Формат отчёта

Не более 15 строк на задачу:

```
P0.1 — TLS
  Изменено: adblock/fetcher.rs, update-adblock.sh, install.sh
  Проверено: sh -n, cargo clippy, ручной прогон с битым URL
  Осталось: —
```

В конце — общий блок:

```
Итог: закрыто N из M задач.
Не проверено: <почему — нет SDK/устройства/инструмента>.
Риски: <что может сломаться у пользователей>.
```

# Порядок работы

Иди строго P0 → P1 → P2 → P3. Внутри приоритета — по номерам. После каждого
приоритета — короткая остановка: перечисли закрытое и явно спроси, продолжать ли.
Не начинай P2, пока P0 не зелёный.
